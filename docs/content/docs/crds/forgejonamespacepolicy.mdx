- **API version:** `forgejo.weebo.io/v1alpha1`
- **Scope:** Cluster
- **Short names:** `fjnp`
- **Guide:** [The allow-list](/docs/guides/allow-list)

Namespace allow-list for the namespaced kinds, enforced by the
admission webhook (CREATE/UPDATE) and re-checked by every reconciler.
It governs the CRs bound to a `ForgejoInstance` (shared by every
namespace); a CR bound to a `ForgejoLocalInstance` is bounded by its
namespace's own token instead.

While no `ForgejoNamespacePolicy` exists, everything is allowed. As soon
as one exists, a namespaced CR is only accepted if some `Allow` rule
matches its namespace and kind and covers the organizations, users and
templates it references — and no `Deny` rule matches. Rules of every
policy are pooled; deny always wins.

## Example

```yaml
apiVersion: forgejo.weebo.io/v1alpha1
kind: ForgejoNamespacePolicy
metadata:
  name: my-namespacepolicy
spec:
  rules:
    - namespaces:
        - team-*
      allowedKinds:
        - ForgejoRepository
```

### `spec.rules[]` [#spec.rules]

| Field | Type | Required | Default | Description |
| --- | --- | --- | --- | --- |
| `allowedKinds` | `string[]` | yes |  | Values: `"ForgejoUser"`, `"ForgejoUserKey"`, `"ForgejoOrganization"`, `"ForgejoTeam"`, `"ForgejoRepository"`, `"ForgejoWebhook"`, `"ForgejoDeployKey"`, `"ForgejoOAuth2Application"`, `"ForgejoAccessToken"` |
| `allowedOrganizations` | `string[]` | no |  | Organizations (Forgejo names) the namespace may manage or reference — a `ForgejoOrganization`'s own name, the owner of its repositories and teams, the target of its org webhooks — whether through a CR or a `remoteName`. Unset: any. On a `Deny` rule: only deny requests referencing one of these. |
| `allowedTemplates` | `string[]` | no |  | Template repositories (Forgejo `owner/name`, `*`, or a prefix glob like `batlehub/*`) the namespace may generate repositories from by name (`fromTemplate.repository`). Unset: any. A template referenced as a same-namespace CR (`fromTemplate.repositoryRef`) isn't governed by this list. On a `Deny` rule: only deny requests referencing one of these. |
| `allowedUsers` | `string[]` | no |  | Users (Forgejo logins) the namespace may manage or reference — a `ForgejoUser`'s own login, the owner of a repository, organization or OAuth2 application, a team member, the holder of an access token or SSH key — whether through a CR or a `remoteName`. Unset: any. Restricting this is what stops a namespace from minting tokens for a privileged account. On a `Deny` rule: only deny requests referencing one of these. |
| `effect` | `string` | no | `"Allow"` | Values: `"Allow"`, `"Deny"` |
| `namespaces` | `string[]` | yes |  | Namespace names, `*` for all, or a prefix glob like `team-*`. |
